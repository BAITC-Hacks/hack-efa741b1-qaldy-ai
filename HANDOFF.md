# Передача Career Quest — 23 сентября 2026

Проект реализует профиль сотрудника, многофакторные рекомендации, завершение активности с пересчётом навыков, HR-агрегаты и двухфазный импорт JSON/CSV. Стартовый набор синтетический: 200 сотрудников, 40 событий, 60 навыков, 2743 записи истории. Правила набора: [README датасета](data/seed/career_quest_dataset/README.ru.md).

## Сдача за 3–5 минут

1. Запустите подготовленный проект по [README](README.md). Проверьте `/health` и `/api/v1/auth/me`: одного ответа health недостаточно, если порт занят другим сервисом.
2. Войдите employee-токеном E0001 и откройте `/journey`. Покажите роль, грейд, навыки и историю; у рекомендации — текущий уровень, требуемый уровень, историю участия и карьерную цель.
3. Завершите доступную добровольную рекомендацию. Покажите точный `before → after`, новый разрыв и обновлённую историю. Уже завершённый неповторяемый шаг не следует предлагать снова.
4. Смените токен на HR. Покажите дефициты навыков, сотрудников без подходящего шага и участие по активностям. Участие приходит из API в `by_event`; отсутствие строк в универсальном `items` не означает отсутствие участия.
5. Покажите AI отдельно: запрос `/api/v1/employees/{id}/recommendations` должен вернуть `recommendation_mode=ai`. Если вернулся deterministic, покажите честный fallback и его причину. Команда приведена в [README](README.md).

Для загрузки файлов жюри используйте `/import`: JSON по структуре employees.json, необязательный activity_history.csv → «Проверить» → прочитать ошибки/предупреждения → «Применить». HR может затем выбрать новый профиль. Для завершения от имени нового сотрудника нужна серверная привязка его ID к employee-токену; импорт не выдаёт доступ автоматически. Подробности: [JURY_DEMO.md](JURY_DEMO.md) и [API](docs/API.md).

## Что подтверждено и что осталось

- Ручной путь seed-сотрудника с завершением и пересчётом проверялся на живом локальном API/SQLite. Web fixture E2E проверяет интерфейс с подменённым API; он не доказывает интеграцию с FastAPI.
- На отдельном изолированном синтетическом запросе реальная модель `gpt-4o-mini-2024-07-18` вернула HTTP 200, статус `completed` и режим ai: около 7,02 с, 677 токенов. Request ID: `req_187ce48f75f54aceaf6ee74f705a934e`; Response ID: `resp_051bb6be1336842a016ab3c8b1239c87d2a9d175542f380775`. Это один запрос. Браузерный стенд аудита на 3002 оставался в deterministic-режиме.
- Сводка аудита: **55 PASS / 3 FAIL / 42 BLOCKED** — 55% пунктов подтверждено, 45% незакрыто. Три FAIL относятся к историческим воспроизведениям; после изменений не все повторены, поэтому они не доказывают три актуальных дефекта. Не объявлять 100 пользовательских тестов пройденными.
- Чистый Docker-запуск, полный браузерный импорт неизвестного профиля, окончательная генеральная репетиция и все пользовательские замеры ≤2 с/AI ≤10 с не подтверждены полностью.
- Demo Bearer-токены и SQLite подходят для локального синтетического показа. Для реального корпоративного запуска нужны production-аутентификация, права доступа и эксплуатация хранилища.

В финальной проверке исправлена обработка HR-участия: используются строки `by_event`, а не пустой `items`; три адресных регрессионных теста прошли. T055 подтверждён в живом браузере: 40 событий, 41 строка таблицы с заголовком; EV_003 — 404 участия / 383 завершения. Финальный web-прогон: **78/78 PASS**, ESLint PASS, TypeScript PASS. Backend smoke: **11/11 PASS** — health, профиль, рекомендации, четыре HR-маршрута и запреты доступа. Живой HR API показал 40 событий и 2744 записи: исходные 2743 плюс завершение из ручного сценария. Эти результаты не заменяют непроверенные пользовательские пункты матрицы.

Текущий стенд аудита использовал web `http://localhost:3002` и API `http://localhost:8002`. Стандартные адреса документированного запуска — 3000 и 8000; не смешивайте стенды и их runtime-базы.

## Воспроизведение проверок

Из `apps/api` с установленными dev-зависимостями: `python -m pytest`.

Из `apps/web`: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`. Для fixture E2E установить Chromium командой `npx playwright install chromium`, затем `npm run test:e2e`.

Завершения и импорт сохраняются в SQLite отдельно от seed. Обычный `docker compose down` сохраняет именованный runtime volume. Не удаляйте данные для подготовки показа: при необходимости используйте отдельный путь `DATABASE_URL` и заново пройдите сценарий на синтетическом наборе.
