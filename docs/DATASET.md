# Формат seed-датасета

Каталог по умолчанию: `data/seed/career_quest_dataset/`. Путь можно переопределить переменной `DATASET_DIR` (для Docker каталог также должен быть смонтирован в контейнер). Loader читает `skills.json`, `employees.json`, `events.json` и `activity_history.csv` как UTF-8.

## Файлы

- `skills.json`: метаданные снимка, каталог навыков и `role_profiles`. Профиль роли задаёт грейд, `required_skills` (уровень требования) и `critical_skills`.
- `employees.json`: метаданные того же снимка и сотрудники. У сотрудника есть `employee_id`, `full_name`, `department`, `role`, `grade`, `work_format`, `preferred_language`, `skills`, `last_review_date`; `career_goal` может отсутствовать или быть `null`.
- `events.json`: метаданные, каталог активностей и события с `event_id`, названием, типом/форматом, длительностью, аудиторией, развиваемыми навыками, prerequisites и будущими сессиями.
- `activity_history.csv`: история назначений и прохождения. Заголовки CSV читаются кодом loader и должны сохранять ожидаемые имена столбцов.

Примеры полей и допустимые значения смотрите в seed-файлах; это каноничный источник схемы. В трёх JSON metadata поля `dataset`, `version`, `as_of_date` должны совпадать. Даты задаются в ISO-формате `YYYY-MM-DD`; уровни навыков и приросты — целыми числами. Грейды: `Junior`, `Middle`, `Senior`, `Lead`.

## Загрузка и проверка

Dataset загружается при создании API service. Ошибки JSON, отсутствующий файл, дублирующийся `record_id` или несовпадающие metadata приводят к ошибке загрузки.

Для HR доступен двухфазный HTTP-импорт: `/api/v1/import/validate` выполняет dry-run, а `/api/v1/import/apply` атомарно применяет ранее проверенный пакет. Формат запроса и требования к заголовкам описаны в [API.md](API.md).

Seed следует считать входным неизменяемым снимком. Завершения через API и применённые импорты не изменяют seed: они записываются в SQLite как runtime overlay, сразу включаются в текущий набор данных и восстанавливаются после перезапуска API.
