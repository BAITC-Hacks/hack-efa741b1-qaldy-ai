# Recommendation engine

## Назначение

Детерминированное ядро выбирает для сотрудника достижимый следующий шаг развития. Оно работает без LLM, использует только факты seed-датасета и возвращает объяснимые факторы оценки.

## Расчёт

1. Выбирается target profile по карьерной цели или следующему грейду.
2. Effective skills строятся из последней оценки и завершений после `last_review_date`; новый уровень не может уменьшить уже достигнутый.
3. Gap равен положительной разнице между требуемым и effective level. Progress считается по суммарным требуемым уровням, поэтому знаменатель стабилен.
4. До scoring исключаются обязательные, уже завершённые и активные события, события без будущей сессии, с невыполненными prerequisites или без полезного skill gain.
5. Оставшиеся кандидаты получают оценку от 0 до 100.

| Фактор | Вес |
|---|---:|
| Gap coverage | 40% |
| Critical skill coverage | 20% |
| Career goal alignment | 15% |
| History fit | 15% |
| Availability | 5% |
| Effort fit | 5% |

После стабильной сортировки выбираются максимум три результата. Небольшой штраф за повтор формата делает выдачу разнообразнее. Каждый результат содержит итоговый score, вклад всех факторов и три причины рекомендации.

## Завершение активности

Команда завершения требует `Idempotency-Key`. Первый запрос добавляет запись в overlay, повтор с тем же ключом возвращает прежний результат без двойного начисления. Затем сервис пересчитывает effective skills, gaps, прогресс и рекомендации и возвращает изменения `before → after`.

## Гарантии текущего этапа

- единая `as_of_date` из метаданных датасета;
- одинаковые входные данные дают одинаковый порядок рекомендаций;
- LLM не участвует в eligibility или scoring;
- исходный seed никогда не перезаписывается;
- overlay процесса является временным и будет заменён SQLite persistence на следующем этапе.

## AI-режим

Если заданы `LLM_ENABLED=true`, `LLM_API_KEY` и `LLM_MODEL`, OpenAI-compatible adapter отправляет в Responses API только обезличенные evidence и top-N валидных кандидатов. Structured Output обязан вернуть те же `event_id` без дублей и по 3–4 доказуемые причины. Неизвестный ID, невалидная схема, отказ или timeout до 10 секунд приводят к детерминированному fallback. Ответ кэшируется по хэшу состояния, версии датасета и кандидатов.
