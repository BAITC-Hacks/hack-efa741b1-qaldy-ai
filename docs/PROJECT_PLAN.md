# Состояние проекта и следующие шаги

Этот документ описывает текущее состояние по исходному коду. Факт наличия тестов или CI не означает, что они прошли на текущей версии; перед демо смотрите актуальный результат GitHub Actions и выполняйте ручной сценарий.

## Реализовано

- Seed loader читает `skills.json`, `employees.json`, `events.json` и `activity_history.csv`; seed остаётся неизменным.
- Профиль сотрудника, целевая роль, эффективные навыки, разрывы и прогресс доступны через employee API.
- Recommendation engine выдаёт до трёх допущенных действий, ранжирует их по нескольким факторам и возвращает объяснимые причины. LLM опционально меняет порядок кандидатов в узком score-band и выбирает поддержанные коды доказательств; сервер проверяет коды и формирует текст причин. Без ключа используется детерминированный результат.
- Завершение активности требует `Idempotency-Key`; completion хранится в SQLite.
- HR API предоставляет разрывы навыков, участие, сотрудников без рекомендации и пробелы каталога. HR-страница читает эти endpoints.
- HR может выполнить dry-run импорт профилей и необязательной истории, затем применить проверенный пакет. Импортированные данные записываются в SQLite и включаются в расчёт.
- Demo RBAC сопоставляет серверные Bearer-токены с ролью и employee ID; employee-токен ограничен одним сотрудником.
- Основная траектория сотрудника находится на `/journey`, HR-обзор — на `/hr`, импорт — на `/import`. Главная `/` и часть дополнительных разделов показывают демонстрационные данные.

Подробные маршруты и форматы — в [контракте API](API.md), свойства ранжирования — в [описании recommendation engine](RECOMMENDATION_ENGINE.md), быстрый запуск — в [SETUP](SETUP.md).

## Границы текущей версии

- Demo Bearer-токены не являются корпоративным identity provider. Не использовать с реальными персональными данными.
- SQLite сохраняет данные между локальными перезапусками при постоянном файле/volume. Сам репозиторий не настраивает надёжное общее хранилище для serverless deployment.
- `AS_OF_DATE` не переопределяет дату расчёта: движок использует `as_of_date` из seed metadata.
- Целевые 2 секунды обычного отклика и 10 секунд для AI заданы в ТЗ. Нагрузочные измерения в репозитории не приложены.
- Интерфейс на RU/KK/EN поддерживается неравномерно; часть дополнительных страниц остаётся прототипом.
- Playwright E2E запускает Next.js с web fixtures. Эти E2E не проверяют работу UI вместе с живым FastAPI.

## Автоматические проверки

`.github/workflows/ci.yml` запускается на `push` и `pull_request` и выполняет:

- API: установка `.[dev]`, затем `python -m pytest`;
- web: `npm ci`, lint, typecheck, Vitest, установка Chromium и `npm run test:e2e`.

`test:e2e` сначала выполняет production build Next.js. Visual и accessibility Playwright projects доступны отдельными командами, но не входят в CI workflow.

## Перед показом жюри

1. На чистом checkout выполнить `docker compose up --build` и убедиться, что web и API доступны.
2. В `/journey` выбрать профиль, показать разрывы, причины рекомендации, завершить активность и показать изменение прогресса.
3. В `/hr` показать все четыре вкладки; в `/import` проверить и применить отдельный синтетический профиль и историю.
4. Перезапустить API и проверить сохранение completion и импорта в настроенном SQLite volume.
5. Проверить актуальный GitHub Actions run и, если демонстрируется Vercel, вручную проверить доступность, переменные окружения и сохранность данных там.

## Идеи за рамками текущего MVP

Публичные рейтинги и награды не входят в решение. Дальнейшими направлениями могут быть production identity/RBAC, полноценная локализация, расширенная HR-аналитика, интеграции с календарём/мессенджерами и production-grade persistence. Это направления развития, а не реализованные функции.
