# План разработки

## Definition of Done проекта

- `docker compose up --build` поднимает web и API без ручных миграций.
- Seed загружается автоматически и идемпотентно.
- Доступен сквозной сценарий: профиль → рекомендация → завершение → новый прогресс.
- Дополнительные профили и история проходят dry-run validation и импорт.
- HR видит дефициты, участие, сотрудников без шага и пробелы каталога.
- Без LLM-ключа работает безопасный детерминированный fallback.
- Backend tests, frontend tests, lint и build проходят.
- README воспроизводим на чистой машине с Docker.

## Этап 1. План, структура и инструкции

Результат этого коммита:

- зафиксирована продуктовая граница;
- выбрана модульная архитектура;
- созданы каталоги `apps/api`, `apps/web`, `data/seed`, `docs`, `tests`;
- задокументированы переменные окружения и целевой способ запуска.

Критерий готовности: документация согласована, пути и команды не противоречат друг другу.

## Этап 2. Запускаемый bootstrap

Статус: завершён в MVP-каркасе с demo vertical slice.

Задачи:

- создать FastAPI healthcheck;
- создать стартовую страницу Next.js;
- добавить Dockerfiles и `docker-compose.yml`;
- добавить базовые lint/test команды;
- проверить запуск web, API и OpenAPI.

Критерий готовности: `docker compose up --build` поднимает оба сервиса.

## Этап 3. Загрузка и валидация данных

Задачи:

- Pydantic-схемы JSON/CSV;
- идемпотентный seed;
- проверка ID, ссылок, enum, диапазонов и дат;
- dry-run import и транзакционное применение;
- диагностируемые ошибки файла, строки и поля.

Критерий готовности: стартовый kit загружается без ручных исправлений, ошибочный fixture отклоняется.

## Этап 4. Доменное ядро

Задачи:

- порядок грейдов и target profile;
- effective skills с учётом `last_review_date`, gain и max level;
- gaps и critical skills;
- eligibility и причины отсутствия шага;
- многофакторный scoring и top-3 diversification.

Критерий готовности: доменные тесты покрывают ключевые и граничные сценарии.

## Этап 5. API и persistence

Задачи:

- employee/profile/trajectory endpoints;
- recommendations endpoint;
- идемпотентное завершение активности;
- HR-агрегаты;
- demo RBAC;
- SQLite repositories и Alembic.

Критерий готовности: основной API-сценарий проходит интеграционным тестом.

## Этап 6. LLM adapter

Задачи:

- OpenAI-compatible interface;
- строгая JSON schema;
- обезличенный evidence payload;
- timeout, cache, validation и fallback;
- сохранение аудита RecommendationRun.

Критерий готовности: timeout, malformed JSON и неизвестный event ID не ломают выдачу.

## Этап 7. Employee UI

Задачи:

- demo login/role switch;
- профиль, цель, навыки и траектория;
- рекомендации и вклад факторов;
- «продолжить начатое»;
- завершение и `before → after`;
- состояния loading, empty, error и fallback;
- каркас локализации `ru/kk/en`.

Критерий готовности: основной пользовательский путь работает через браузер.

## Этап 8. HR UI и импорт

Задачи:

- gap dashboard;
- participation view;
- сотрудники без рекомендации;
- catalog gaps;
- фильтры;
- upload, dry-run report и apply.

Критерий готовности: HR может импортировать проверочный профиль без изменения кода.

## Этап 9. Проверка и подготовка демо

Задачи:

- unit, integration и Playwright smoke test;
- проверка лимитов 2/10 секунд;
- запуск с чистого clone;
- демо-сценарий на 3–5 минут;
- синхронизация README с кодом.

Критерий готовности: все команды README воспроизводимы, известные ограничения перечислены.

## Приоритеты

### Must-have

- профиль и траектория;
- 1–3 объяснимые рекомендации;
- корректное обновление прогресса;
- HR-view;
- импорт проверочных данных;
- одна команда запуска.

### Backlog после MVP

- награды и внутренняя валюта;
- peer recognition;
- прогноз риска оттока;
- календарь и мессенджеры;
- production SSO;
- расширенная аналитика и мобильная оптимизация.
