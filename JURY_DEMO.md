# Демонстрация Career Quest

Сценарий ниже — короткая инструкция для воспроизведения обязательного пользовательского пути и импорта проверочного профиля.

## Запуск

Из корня репозитория с установленным Docker/Compose v2:

```powershell
docker compose up --build
```

Открыть `http://localhost:3000`. Для чистого Compose employee-вход: `local-demo-employee-token-2026` (E0001), HR-вход: `local-demo-hr-token-2026`. Если существует `.env`, действуют его настройки: не показывать реальные значения в записи демонстрации. Эти публичные demo-строки подходят только для синтетического локального стенда.

При уже установленных Python- и Node-зависимостях Windows-альтернатива:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

Это запуск подготовленного локального окружения, он не устанавливает зависимости. Убедиться, что порты принадлежат именно этому приложению: `/health` должен быть доступен, а `/api/v1/auth/me` с настроенным Bearer-токеном должен возвращать роль, а не 404. Прерывать показ при неверном сервисе, не выдавать его данные за результат проекта.

## Показ, ориентир 4–5 минут

1. **Профиль, 45 секунд.** Войти employee-токеном через меню профиля. Открыть `/journey`: роль, текущий грейд, стаж, фактические навыки, история с датами и целевой грейд. Назвать расчётную дату набора — 2026-10-01.
2. **Рекомендация, 60 секунд.** Показать 1–3 доступных добровольных шага. На одном объяснить текущий грейд, фактический и требуемый уровень навыка, историю участия и цель следующего уровня. Сопоставить ожидаемый прирост с `gain/max_level` события. Не утверждать, что наименьший навык всегда первый.
3. **Прогресс, 45 секунд.** Зафиксировать текущий уровень и разрыв; завершить одну доступную рекомендацию. Показать `before → after`, обновлённую историю и траекторию. Повторное нажатие не должно начислять рост второй раз. HR не завершает активность за сотрудника.
4. **HR, 45 секунд.** Сменить токен на HR, открыть `/hr`. Показать частые дефициты, сотрудников без подходящего шага, участие. Объяснить, что это агрегаты, а публичного рейтинга результативности нет.
5. **Импорт жюри, 60–90 секунд.** Выполнить шаги ниже, выбрать новый профиль и сравнить объяснение с данными жюри. Не обещать окончательный результат до успешного validate/apply.

Показывать режим рекомендаций явно. Без ключа используется детерминированное многофакторное ядро; это не ответ внешней модели. Включённый AI лишь переставляет проверенных кандидатов в допустимом диапазоне; объяснения сохраняют факты движка. Внешняя модель в этом аудите не вызывалась, датасет не отправлялся наружу.

## Импорт неизвестного профиля

1. Получить от жюри `employees.json` в структуре исходного файла: объект `meta` с теми же `dataset`, `version`, `as_of_date` и массив `employees`. Один профиль тоже помещается в массив. Использовать новый уникальный `employee_id`, существующие role/grade и `skill_id`; уровни — целые 0–5. Точный перечень полей приведён в [README набора](data/seed/career_quest_dataset/README.ru.md).
2. Если есть история, сохранить её в UTF-8 CSV с точным заголовком `record_id,employee_id,event_id,date,due_date,status,completion_pct,score,feedback_rating,assigned_by`. Ссылки на сотрудников/события должны существовать; статусы не заменять друг другом.
3. Войти как HR, открыть `/import`. В первое поле загрузить JSON, во второе — необязательный CSV. Нажать «Проверить». Прочитать `valid`, `errors`, `warnings`, `counts`, `preview`. При ошибке исправить входной файл; исходный набор не должен изменяться от dry-run.
4. Только при `valid=true` нажать «Применить». Проверить числа вставленных/повторных строк. Токен проверки действует 15 минут. Перейти в `/journey` и выбрать сотрудника, затем в `/hr` проверить его влияние на агрегаты.
5. Для завершения от имени **нового** сотрудника оператор должен заранее добавить его ID и отдельный уникальный demo-токен в `DEMO_EMPLOYEE_TOKENS` и перезапустить API с этой конфигурацией. Импорт сам по себе не выдаёт employee-доступ. После этого войти токеном нового сотрудника. Полный показ seed-профиля E0001 не требует этой подготовки на чистом Compose.

JSON можно передать и как пакет `{"employees_json": <исходный объект>, "activity_history_csv": "<CSV>"}`. HTTP-путь и заголовки: [docs/API.md](docs/API.md). SQLite хранит изменения отдельно от seed; стандартный `docker compose down` сохраняет runtime volume.

## Риски показа

- На машине уже могут работать несовместимые сервисы на 3000/8000; общий `/health` не подтверждает их принадлежность проекту.
- У конкретного профиля может не быть подходящих активностей: показать честную причину и запись HR, а не выдуманный шаг.
- Новый профиль не получает demo-учётную запись автоматически; подготовить соответствующий токен для этапа завершения.
- Реальный AI, чистый запуск и скорость пользовательского интерфейса подтверждаются только отдельными измерениями; результаты API/unit-тестов не подменяют эти проверки.

Во время репетиции записать фактическое время каждого этапа, устройство, режим dev/production, сеть и AI-модель. Цели ТЗ: интерфейс ≤2 с, AI ≤10 с; это требования, не результаты измерения.
